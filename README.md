# SlotWise — фронтенд

Веб-интерфейс SlotWise — сервиса планирования экзаменов, консультаций, предзащит и защит.

## Технологии

React, TypeScript, Vite, Material UI, MobX, React Router и Axios.

## Запуск с бэкендом

Требуются Node.js 22 или новее и npm.

1. Возьмите `sprint/2` обоих репозиториев после мержа интеграции. После релиза спринта используйте `main` обоих репозиториев.
2. Запустите `slotwise-back`. При самостоятельном запуске с чистой базой понадобятся JDK 25, Docker Desktop и переменные `SLOTWISE_ADMIN_EMAIL` и `SLOTWISE_ADMIN_PASSWORD` для первого администратора. Команда запуска из `slotwise-back` — `./gradlew :app:bootRun`, в Windows PowerShell — `.\gradlew.bat :app:bootRun`. [README бэкенда](https://github.com/vk-ab-schedule/slotwise-back)
3. Проверьте `http://localhost:8080/actuator/health`. Для уже запущенного бэкенда используйте его адрес в следующем шаге.
4. В корне `slotwise-front` создайте или обновите `.env.local` с такими параметрами.

   ```env
   VITE_MOCK_API=false
   SLOTWISE_API_PROXY_TARGET=http://localhost:8080
   ```

5. Установите зависимости и запустите Vite в каталоге `slotwise-front`.

   ```sh
   npm ci
   npm run dev
   ```

6. Откройте адрес из терминала, обычно `http://localhost:5173`, и войдите с учётной записью бэкенда. Сгенерированные типы входят в репозиторий, поэтому этих шагов достаточно для запуска.

После изменения `.env.local` перезапустите Vite. Vite проксирует `/api` на `SLOTWISE_API_PROXY_TARGET` в `dev` и `preview`. Авторизация использует cookie `SESSION` и `XSRF-TOKEN`.

### Проверка подключения

После входа под администратором откройте «Пользователи» или «Данные вуза» и обновите страницу. На вкладке Network в браузере будут ответы `200` от `GET /api/auth/me` и запросов к справочникам. Чистая база может сначала показать пустые списки.

На чистой базе администратор может создать пользователей и задать им пароли через «Пользователи», затем загрузить справочники через «Данные вуза» → «Загрузить JSON». Организатор создаёт сессию с открытым сбором, добавляет участника на вкладке «Участники и ресурсы», после чего участник может сохранить и отправить занятость.

На текущем `sprint/2` сервер отвечает `501` на расчёт, просмотр расписания, ручное редактирование справочников и запись типов событий. В этих случаях интерфейс показывает сообщение о недоступной операции.

## Запуск демо

Установите `VITE_MOCK_API=true` или уберите переменную из `.env.local`. Запустите `npm ci` и `npm run dev` в каталоге фронтенда. Для входа используйте `admin@example.test`, `organizer@example.test`, `teacher@example.test` или `student@example.test` с любым непустым паролем. Демо-экраны запросов на перенос, сценариев и экспериментов доступны в этом режиме.

### Демо расписания и расчёта

1. Под организатором откройте сессию «Защиты ВКР · P3410». На вкладке «Участники и ресурсы» добавьте «Онлайн-площадку» в список ресурсов сессии и сохраните выбор. На вкладке «События» создайте консультацию с научным руководителем для студента «Смирнов Александр», если её ещё нет.
2. Откройте «Расписание и расчёт» → «Запуск расчёта». Нажмите «Проверить данные», затем запустите расчёт. После очереди и выполнения откроется черновик с календарём и метриками.
3. Для проверки тайм-аута запустите расчёт с лимитом 1 секунда. Статус «решение не найдено» появится после опроса, предыдущие варианты останутся доступны.
4. Под студентом или преподавателем откройте «Моё расписание». На неделе 15–21 июня 2026 есть опубликованные демо-события. Нажмите название события, чтобы увидеть детали и участников.

Демо использует события и версии сессий из F4. Расчёт и метрики моделируются в браузере. Для просмотра участниками используется отдельный опубликованный демо-вариант.

## Генерация типов API

Источник типов — DTO и контроллеры Java. Springdoc отдаёт их контракт в OpenAPI, а `openapi-typescript` преобразует его в `src/api/schema.d.ts`. Клиент Axios использует из этого файла маршруты, HTTP-методы, параметры, тела запросов и ответы. DTO с датой и временем передаются ISO-строками. Адаптер пагинации вычисляет число страниц для интерфейса из серверных `total` и `size`.

С запущенным бэкендом на порту `8080`:

```powershell
npm run api:generate
npm run api:check
```

Можно указать другой URL или экспортировать JSON через Gradle без запуска БД:

```powershell
# В slotwise-back
.\gradlew.bat :app:exportOpenApi
# В slotwise-front
npm run api:generate -- ../slotwise-back/app/build/openapi/slotwise.json
npm run api:check
```

Коммитьте вместе `openapi/slotwise.json` и `src/api/schema.d.ts`. CI запускает `api:check` по сохранённому JSON без подключения к бэкенду. Для смены контракта повторите генерацию из актуальной версии бэкенда. Декларации правятся через Java/OpenAPI и генератор.

## Сборка

```sh
npm run api:check
npm run lint
npm test
npm run build
npm run preview
```

Готовые файлы сборки находятся в каталоге `dist`. При публикации статики настройте проксирование `/api` на том же домене и соберите фронтенд с `VITE_MOCK_API=false`.
